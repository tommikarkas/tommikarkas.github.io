The symptom was precise: every open socket dropped 61 seconds after the last message, on the office network only. Precise symptoms are gifts. They usually mean a configured number rather than a bug.

What the proxy does

Corporate proxies close idle tunnels. Ours has a 60-second idle timeout, which the WebSocket spec has nothing to say about. The client library's default ping interval is 0, meaning never.

If a connection can be idle, something in the path will decide it is dead.

Reproducing it locally

  • Run mitmproxy with --set connection_strategy=lazy.
  • Set its idle timeout to 10 s so the wait is short.
  • Open a socket and send nothing.
